| 2026-09-29 | Cradle Migration 0.2.0 exports **one `.cradle` file** and imports it in **one step**. The file is a standard ZIP (entries stored, ZIP64) holding the unchanged format-1 manifest and part ZIPs; the export's new `bundle` phase writes it resumably (whole files per step, committed offset in the cursor) and then removes the separate parts. The import's new `unpack` phase extracts it (flat, or inside one folder; stored or deflated) before the unchanged preflight. A browser import is created with `auto`: a report without blocking problems continues straight into staging, and the tab that started it (sessionStorage flag) requests the switch-over token itself and finally opens the login page (`redirect_to` = the import's outcome). The single confirmation is a dialog before the upload starts. The command line keeps the review and switch-over stops unless `--yes`. Everything is inside the plugin, so running sites update by replacing `cradle-migration` alone. | Owner: two kinds of files and three decisions were too complicated; export and import must be one click each, followed by the login page. | A new archive format version with entries directly in the container (would change every importer check; format 1 stays valid inside the container); keeping the review/approval screen (owner wants one step; blocking problems still stop the import and the report stays on the job); auto-switching in any tab that opens the job (a stale link could then switch a site over; only the starting tab may); ZipArchive for writing (writes the whole container in one request, not resumable). | cradle-migration, tests |

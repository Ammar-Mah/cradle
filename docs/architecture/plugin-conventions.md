# Cradle feature-plugin conventions

Applies to every `packages/plugins/cradle-<feature>/` package. Read with `core-api.md`.

## Package layout

```
cradle-<feature>/
  cradle-<feature>.php   Bootstrap only: header, constants, autoloader, lifecycle hooks, module registration, core-missing guard.
  src/                   Namespaced classes Cradle\<Feature>\... (class-foo-bar.php for Foo_Bar).
  admin/                 Admin screens and admin-only handlers (Cradle\<Feature>\Admin\...).
  assets/css, assets/js  Independently registered, conditionally enqueued files. Vanilla JS, no JSX, no build step.
  blocks/<name>/         block.json + editor.js (+ style.css, view.js) when the feature has blocks.
  components/<name>/     component.json descriptors when the feature renders reusable components.
  languages/             .pot generated by scripts (may be absent until generated).
  docs/                  Feature contract, data model, lifecycle and security notes.
  uninstall.php          Retain by default; purge only when cradle_uninstall_policy[<id>] === 'purge'.
  AGENTS.md, CLAUDE.md   Package scope, supported hooks, feature risks, lifecycle rules (CLAUDE.md = "@AGENTS.md" wrapper).
```

Skills are **not** authored inside packages; `scripts/sync.php` injects them from the canonical `skills/`.

## Required behavior

- Headers: `Requires Plugins: cradle`, `Requires PHP: 8.3`, `Requires at least: 7.1`, `Update URI: false`, `Cradle Module: <id>`, `Text Domain: cradle-<feature>`.
- Runtime guard when core is missing (admin notice for `activate_plugins` users; no fatal; no data changes).
- Descriptor registered on `cradle/register_modules`; feature hooks attached only in `boot` (module ready).
- Activation: refuse network activation on multisite; create defaults/schema idempotently; never generate content.
- Deactivation: unschedule own cron, release own locks, flush rewrites if routes were added; keep data.
- Every privileged mutation: capability (and object capability) check + nonce for browser requests + correct HTTP method. REST routes have deliberate `permission_callback`. GET never mutates.
- Validate by type/range/allowlist before normalizing; escape by output context; prepared SQL; allowlisted identifiers.
- Load admin assets only on the screens that use them; frontend assets only where the feature renders.
- Record privileged operations with `cradle_log_activity()` (no secrets).
- Use logical CSS properties (RTL), visible focus, labelled controls, `prefers-reduced-motion`.
- No third-party runtime libraries, no jQuery-based custom code, no remote requests unless the feature requires them (then `wp_safe_remote_*` with allowlists and size/time limits).

## Testing in the sandbox

- Source edits are mirrored into `wp/` automatically by a Claude Code hook; `php scripts/sync.php <package>` does it manually.
- Activate with `php scripts/sandbox/activate.php plugin <slug>`; check with `… status`.
- Tests live in `tests/integration/<feature>.php` and use `tests/lib/bootstrap.php` helpers:
  `cradle_test()`, `assert_*()`, `skip_test()`, `cradle_test_user( $role )`, `cradle_test_cookies( $user_id )`,
  `cradle_test_nonce( $user_id, $session, $action )`, `cradle_test_http( $method, $path_or_url, $args, $user_id, $session )`.
  Run `php tests/run.php --suite=<feature>`. Exercise an allowed role **and** a denied role for every mutation.
- The sandbox is shared with other work: never deactivate core or other packages, never switch the theme, never delete data you did not create, clean up your test fixtures, and leave risky features (for example custom login routing) disabled when you finish.
- Never type passwords into forms; tests mint auth cookies directly.
